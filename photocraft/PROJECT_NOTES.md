MOSS AnyPaint (unreleased) is an Edit method and a manual Remove method: MOSS-Image Base, the AnyPaint rank-32 adapter, the Base 8-step DMD2 adapter and the three `moss-anypaint` nodes. Discovery requires all three nodes, the `moss_image` CLIP type, Base (never SFT), the Qwen3.5 9B encoder, `flux2-vae_small` and both adapters. INT8 is preferred, but the BF16 export of the same Base and encoder is accepted so existing MOSS installs need no second copy; `kromoss_8-step_dmd2.safetensors` is byte-identical to `lora_dmd2.safetensors`. The adapter's only reference is the masked canvas, so attachments are refused. Prompts describe the finished picture. Native MOSS already uses shift 5; do not add a sampling-shift node. The graph scales the hard selection support bilinearly and thresholds above zero for `MOSSAnyPaintPrepare` (padding 0, reference 384, seam 32), samples eight Euler steps at CFG 1 with one sampler per seed, then restores the crop through the same support. AnyPaint repaints rather than adjusts: the new object can move or shrink, so a wide inward Auto-feather on a tight selection lets the original show through the soft band (seen at 65%; clean at the 10% default). Judge results with a realistic feather and compare against the raw ComfyUI output before blaming the model. For Remove, `MOSSAnyPaintPrepare` replaces the hole with the median of the preserved pixels in its semantic reference, so no locator or clean plate is needed. OpenFill's generic "continue the surrounding background" prompt made it invent a cartoon face with fake lettering on a smooth gradient; `MOSS_ANYPAINT_REMOVAL_PROMPT`, which describes an empty, evenly continued scene, removed all eight frozen clean-plate objects without inventing anything. Its scores still trail LaMa and Qwen Lightning, so Automatic keeps H3 and removal advice does not suggest AnyPaint. Run the shared suite as `python -m unittest discover -t . -s tests`; without `-t .` the first module cannot import `openfill`.

FLUX 3 Image Klein (unreleased) is an Edit method and a Remove method, using Black Forest Labs' ComfyUI packaging of the NVFP4 distilled model. Discovery requires the `ReferenceMultiLatent`, `ModelSamplingFlux` and `EmptyFlux2LatentImage` nodes, the `flux3` CLIP type, and the diffusion model, Qwen3-VL 4B encoder and FLUX.2 VAE at their exact `FLUX-3-Image-Klein/` paths; a bare file name or a root-level `flux2-vae.safetensors` is a different file and does not count. Only the NVFP4 diffusion model is accepted. As in FIBO's Replace mode, the selection is greyed in the single reference image (`ReferenceMultiLatent` at 1 MP); no attachments are accepted. Sampling follows the published recipe: 16 Euler/simple steps at CFG 1 with a fixed log(16) shift, at about 4 MP in multiples of 16 with a 768 px short-side floor and a 4.5 MP cap. Edits start from an empty latent and their instruction is wrapped for the grey region. Removal sends `FLUX3_REMOVAL_PROMPT` as is and samples as latent inpainting: the grey guide is VAE-encoded and the selection is its noise mask, so the exterior latent is held to the original at every step. From an empty latent the model redrew the whole crop with a colour drift of up to about 25 levels, which raters flagged as a visible outline on 26 of 54 removals; latent inpainting raised its removal rating from 2.7 to 3.4 stars. Both paths composite the result through the hard selection support once, and PhotoCraft applies the soft alpha. The model could still paint the hole a few levels lighter or warmer than its surroundings (a faint rectangle on flat walls and illustrations; the exterior itself matched, so the outside-ring `seam_field` saw nothing). After a FLUX 3 removal, `quality.edge_field` compares the original in a band just outside the edge with the fill just inside it, per cell of at least 32 px so brick or wood texture samples alike on both sides, drops cells above 24 levels or far from the edge-wide median as content, drops cells whose bands spread wider than 32 levels (median absolute deviation) because on a pattern such as gingham the band medians report which part of the pattern fell in each band rather than drift (correcting by them turned a matching fill's whites mint), and spreads the rest over the fill with `apply_seam_field`: full strength within 32 px of the edge, fading out over the next 64 px, because spreading the edge offset across a large selection over a vignette drew the removed figure as a dark ghost. Each cell pools its 3 x 3 neighbourhood so an edge along a cell boundary is still measured. It is for removals only (it assumes the background continues across the edge) and follows `seam_correction`.

## 0.27.0: Automatic Edit, shadows and attached parts (November 26, 2026)

- `edit_plan.py` turns an edit's words and selection into Automatic Edit's plan: `shape` (whole, swap, spot or look), then `plan` (the models in order, each `Step` with its label, settings, prompt and seed offset). `SETTINGS` and `MODES` are the values the ratings were made with; `Service._edit_auto` runs every step inside `_choices` so a job's values never reach the saved settings. `App.option` reads a job's choice first, then the saved setting; `App._job_padding` does the same for `context_padding`.
- `removal_plan.SETTINGS` does the same for Automatic Remove. `cast.py` asks the selection model for the selected object's shadow and reflection and keeps only finds that touch or mirror it (look-alikes: nearest one wins); `rim.py` adds the object's own edge and contact shadow on plain surroundings (flat average and fitted plane, capped at 40% of the selection). Both run in `Service._remove` before the repair and add notices.
- `whole.py` and `pieces.py` add attached parts and strings to a selection; `wevisone.clean_matte` tidies the model's matte, and `WeVisOne._courtesy_client` asks an engine that is already running (two short knocks for a remote one) and starts the local engine only when the removal would start it anyway.
- `ComfyBackend` and `WeVisOne._instances` clear the server's picture cache once and repeat a job when ComfyUI's loader has run out of address space (`ComfyExecutionError.is_loader_exhausted`).
